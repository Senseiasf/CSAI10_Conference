# Проверка графовой логистики CSAI 2026

Актуализация 11.11.2026: последующие исправления и оставшиеся ограничения описаны в
[csai2026_search_ranking_audit.md](csai2026_search_ranking_audit.md). Ниже сохранена история предыдущего этапа.


Работа участника 2 для режимов C3 и C4. В строгом режиме `GraphService` использует рейсы и трансферы из демонстрационного каталога Neo4j и возвращает причину, когда обязательную часть маршрута подтвердить не удалось.

## Что изменено

- Cypher отбирает прямые рейсы и рейсы со стыковкой от 60 минут в обоих направлениях. Запрос «без пересадок» ограничивает оба плеча прямыми рейсами. Выбор по времени вылета, цене и длительности применяется к допустимым кандидатам.
- Удалена генерация недостающих рейсов и расписаний. Некорректное время, отсутствие рейса или неподходящий трансфер дают отказ с `reason_code`. В составном туре отказ останавливает сборку, а обратный рейс ищется из аэропорта второй остановки.
- Валидатор выбирает первую допустимую пару рейса и трансфера. Размер группы учитывается до выбора. Известная вместимость сохраняется на ребре и возвращается вместе с результатом. Для каталожных трансферов без значения возвращается `capacity_status=unknown`.
- В Мале окно гидросамолёта проверяется по времени готовности после выхода из аэропорта. В Петербурге закрытие применяется к трансферу с указанным временем проезда через разводной мост. Для сценария Васильевского острова в каталог добавлен демонстрационный маршрут через мост и сохранён существующий объезд через ЗСД.
- При самостоятельном проезде расчёт охватывает перелёты. Время и стоимость дороги до отеля пользователь уточняет отдельно.
- Сидирование сначала создаёт все аэропорты и отели, затем связи. Это сохраняет межгородские рейсы между аэропортами, описанными в разных разделах каталога.

## Проверка на Neo4j 5.21.0

Из каталога дважды загружены 9 направлений, 22 аэропорта, 1 327 отелей, 276 рейсов и 1 350 рёбер трансфера из аэропорта до отеля. Счётчики совпали в обоих прогонах. До изменения порядка сидирования первый прогон показал 258 рёбер рейсов.

В каталожном сценарии позднего прилёта в Петербург выбран объезд через ЗСД. Катер до Sun Siyam Olhuveli принят для восьми человек и отклонён с `transfer_capacity` для девяти. Сквозной тест через `MCPTools` и реальный Neo4j покрывает отсутствие рейса, пороги 59/60 минут, отсутствующий и неподходящий обратный рейс, смену трансфера, окно гидросамолёта и моста, испорченное время, самостоятельный проезд и возврат из другого города.

Для повторения интеграционного теста из `backend` задайте `CSAI_NEO4J_TEST_URI` для выделенного тестового Neo4j без аутентификации и выполните `python -m pytest -q tests/test_graph_validation_neo4j.py`. Тест создаёт временные узлы и удаляет их по идентификатору фикстуры.

В контрольном запуске на исходном коммите `e1e5f03` воспроизвелись три зависимых от календаря падения в тестах REST, SSE и сдвига дат. Они вызваны тем, что тесты ожидали поездку на 10 ноября 2026 года, а запуск выполнялся 11 ноября.

## Аудит после графовой правки

### Граф и границы эксперимента

- В исходном каталоге для 100 из 276 записей рейсов отсутствовала обратная запись для той же пары аэропортов. Для сравнения C1–C4 стоит публиковать отдельно долю запросов, где агент смог предложить хотя бы один допустимый тур. Отбор строгого режима уменьшает число доступных вариантов.
- В JSON есть 1 361 запись трансфера. Neo4j загружает 1 350 аэропортовых и 8 межотельных рёбер. Три аэропортовые записи HKT ссылаются на отсутствующие идентификаторы: `thai_katathani_resort`, `thailand_tbo_the_boathouse_phuket_34`, `thailand_tbo_centara_grand_beach_reso_146`. README использует наблюдаемые числа и актуальную ссылку для клонирования.
- Временные окна, вместимость контрольных трансферов и цены заданы демонстрационными данными. Для большинства рёбер вместимость неизвестна. Полнота проверки зависит от полей каталога.
- Составной тур проверяет в Neo4j первый прилёт с трансфером и обратный рейс из последнего аэропорта. Внутренний переезд может браться из демонстрационного справочника. Стыковка всех сегментов по календарю и время проезда второго наземного плеча остаются за пределами этой проверки. Для первого сквозного сравнения использовать одногородские туры либо отдельно размечать составные.
- `strict_graph_validation=False` доступен через `MCPTools`. Этот флаг ослабляет ограничения по пересадкам и временным окнам, но по-прежнему читает граф. Для полноценного SQL-базового режима нужен отдельный путь получения кандидатов из каталога. Общий переключатель C1–C4 относится к ветке интеграции участника 1.

### Поиск

- `generate_text_embedding` хэширует целые слова через SHA-256. На локальном вызове действующей функции косинус между «море» и «море,» равен 0,00418, между «море» и «морю» — −0,19383, между «море» и «пляж» — 0,06349. На сыром косинусном сравнении девяти каталожных векторов добавление запятой к запросу «хочу море и горы» меняет top-3 с `turkey, thailand, sochi` на `thailand, georgia, turkey`. Это проверка эмбеддингов в Python. SQL-выдача PostgreSQL/pgvector в этом прогоне не измерялась.
- `AgentService.search_destinations_vector` отдельно применяет ручной список морских направлений, поэтому гибридная выдача может отличаться от сырого косинуса. После замены представления нужно заново рассчитать векторы при сидировании и отдельно проверить синонимы, словоформы и пунктуацию через реальный PostgreSQL.

### Ранжирование

- `score_features_batch` загрузил штатный `.cbm` и вернул движок `CatBoostRanker (.cbm)`. При одинаковых остальных признаках Турция, ОАЭ, Таиланд, Мальдивы и Египет передают одинаковую категорию `Стамбул -> Анталья -> Каппадокия` и получили один скор 4,73718. Сочи с отдельной категорией получил 4,32632. Контрольная сумма весов SHA-256 — `0288be650fd2f276fb349573948b6246fa9bd4dd27755997a05642f556a253d1`. Различимость направлений нужно восстанавливать одновременно в обучении и инференсе.
- В одногородском подборе `AgentService` после фильтрации по бюджету может пересортировать допустимые пакеты по звёздам, используя ML-скор вторым ключом. Для сравнения эвристики и CatBoost нужно подать обоим ранжировщикам одни и те же допустимые пакеты и фиксировать фактически применённый порядок.
- Исходный JSONL для обучения отсутствует. И в `train_ltr.py`, и в примере методички тестовая выборка используется для выбора лучшей итерации. Для воспроизводимых метрик выделить независимые train/validation/test по `group_id` и обеспечить представленность всех архетипов в тесте. В примере методички группы берутся подряд, хотя генератор выдаёт их блоками по архетипу. Пример генератора в методичке назначает метки формулой по архетипу. В статье такие метки следует описывать как синтетические эвристические предпочтения. Результаты модели выше проверяют инференс. Для сравнения качества нужны независимые метки предпочтений.

### Что скорректировать в бенчмарке

Пример из методички моделирует поиск и логистику в Python по JSON. Он измеряет этот автономный расчёт. Для статьи прогонять вызовы приложения с PostgreSQL/pgvector и Neo4j, оценивать выполнимость по независимой разметке и рядом показывать покрытие запросов. При нескольких допустимых направлениях выражение `any(...)` в примере считает HitRate@2. Для Recall@2 нужно делить число найденных релевантных направлений на число всех релевантных для запроса. Для парных сравнений достаточно NDCG@2 и Pairwise Accuracy.

В тестах REST/SSE зафиксирована дата 30 октября 2026 года, а тесты относительных сдвигов передают её через параметр `today`. Рабочая логика календаря используется в обоих случаях.

Итоговый запуск прошёл с 249 тестами Python, включая интеграционный тест с Neo4j, и 6 тестами JavaScript.
