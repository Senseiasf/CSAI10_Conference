# Мягкие предпочтения и проверка C3/C4

Ветка `codex/benchmark-preference-ranking` продолжает эксперимент с
контрфактическими парами. Действующие веса CatBoost сохранены. Метки
новых запросов и качественных пар зафиксированы в коммите `870e1fb`.

## Изменения в пайплайне

- `LLMService` передаёт отдельный слот `soft_preference` с атрибутом
  и, если он назван, пределом доплаты. Приоритеты не попадают в общий
  бюджет. В известных русскоязычных формулировках предел извлекается
  из текста, включая пробелы в числах, тысячи и десятичную запятую.
  Неподтверждённый численный лимит от LLM помечается для уточнения.
- Жёсткая фильтрация остаётся до ранжирования. «Только прямой рейс»
  исключает стыковки, а «прямой, если доплата до 15 000 ₽» оставляет оба
  допустимых варианта. Правило сравнивает цену тура с преимуществом
  с ценой самого дешёвого допустимого тура. При точном совпадении с
  лимитом преимущество допускается. Если подходящей доплаты нет,
  первым становится самый дешёвый тур.
- Без названной суммы текущий первый вариант сохраняется, а подходящий
  по мягкому предпочтению тур может попасть в альтернативы. Подбирать
  условный предел доплаты из архетипа не требуется. Обрабатывается одно
  явно выделенное предпочтение. Для прямого рейса мягкий атрибут относится
  к вылету туда, жёсткое требование проверяется на обоих направлениях.
- После ранжирования C3/C4 сохраняют первый тур и резервируют место
  для другого найденного направления при наличии допустимого варианта.
  Остальные места заполняются по исходному порядку. `--top3 score`
  оставляет тройку по скору. Обе политики оцениваются в одном прогоне
  на общем отсортированном пуле.

## Эксперимент с явной доплатой

`check_csai_preferences` берёт реальные связные пути из Neo4j,
восстанавливает обе стороны каждой пары, проверяет допустимость
и сверяет итоговую цену с замороженной выборкой. Общее число гостей,
длительность и бюджет заданы эталонными слотами. Доплата извлекается
из исходного текста, затем вызывается тот же `rank`, что и в C3/C4.

На всех **832** текстах правильно извлечены атрибут и предел.
На отложенных **368** запросах C3 и C4 без нового правила дали
184 правильных ответа, с правилом — **368**. Это проверка известного
условия по каталожным предложениям. Провайдер LLM в этой среде
не настроен, сквозной вызов внешнего NLU не измерялся.

## Тройка на новых запросах

Собраны 30 новых синтетических запросов на том же каталоге. Десять
содержат описательные подсказки о направлении, десять допускают
два названных направления, десять задают одно. Проверка использует
реальные MiniLM, Neo4j и CatBoost с эталонными жёсткими слотами.

| Режим | Success@1 при обеих политиках | Тройка по скору | Тройка с разнообразием |
| --- | ---: | ---: | ---: |
| C3 | 24/30 | 24/30 | 30/30 |
| C4 | 24/30 | 24/30 | 30/30 |

Для каждой конфигурации первый вариант сохранился во всех запросах,
а место для второго направления дало шесть дополнительных успехов.
Набор мал и создан на одном снимке каталога. 30/30 не следует
переносить на реальные запросы или другие каталоги.

Повторный прогон CSAI-200 дал для C3 **122 → 156** и для C4
**123 → 156** успехов в тройке. Success@1 сохранился на 122/200 и
114/200 соответственно. Все выданные пакеты C3/C4 в этих прогонах
прошли проверки логистики и жёстких условий.

## Сравнение на компромиссах без точного порога

Отдельно выбраны 24 пары с отложенных направлений. Тексты и эталон
созданы для качественных компромиссов. В разметке использованы
карточки туров, исходный запрос и явное обоснование каждого решения,
скоры ранжировщиков на этом этапе скрыты. Разметку выполнил Codex как
единственный оценщик. Это пилот, а не разметка реальными туристами
или независимыми экспертами. Три неоднозначные пары оставлены как TIE.

На 21 размеченной паре сортировка по цене, C3 и C4 получили
**10/21** каждая. C4 исправил две ошибки C3 и добавил две другие.
Точный парный тест даёт p = 1,0. Преимущество C4 на этой пробе
не подтверждено. Существующее обучение CatBoost не менялось по
результатам test. Для убедительной оценки нужен более крупный
набор независимых меток по мягким компромиссам и отдельное обучение
на признаках, действительно доступных в каталоге.

## Воспроизведение

Запустить из `backend/` с Neo4j, заполненным тем же каталогом:

```powershell
python -m unittest discover -s tests -q
python -m app.scripts.check_csai_preferences
python -m app.scripts.run_csai_benchmark --queries app/data/csai_top3_holdout.json --output-dir ../experiment_outputs/top3_holdout
python -m app.scripts.run_csai_benchmark --output-dir ../experiment_outputs/preference_csai200
```

Файлы `explicit_predictions.csv`, `qualitative_predictions.csv`
и `preference_audit.json` сохраняются в `experiment_outputs/preferences/`.
Сравнение политик тройки и исходные ответы сохранены в
`top3_comparison.csv` и `per_query_audit.json` в соответствующем каталоге прогона.
Прошли 44 теста, включая границу доплаты, отделение мягкого условия от
жёсткого, проверку неподтверждённой суммы, разные форматы рублей и
сохранение первого результата.
