# Ostrovok AI Travel Agent (Трек: AI-агент для Островка)

Интеллектуальный AI-агент для Островка, который превращает одно сообщение путешественника в готовый сценарий поездки «под ключ» с верификацией логистики стыковок через графовую базу Neo4j и семантическим подбором направлений через pgvector.

## Быстрый старт

Развёртывание решения полностью автоматизировано и не требует дополнительных ручных команд:

## Зависимости и переменные окружения

**Рекомендованные системные ресурсы:**
- 2–4 CPU cores
- 4–6 GB RAM
- Свободный порт `8080`

**Зависимые сервисы (входят в `docker-compose.yml`):**
- **PostgreSQL 16 + pgvector** (сервис `db`): реляционная модель, профили, корзина и семантический векторный поиск.
- **Neo4j 5 Community** (сервис `neo4j`): графовая база знаний для проверки стыковок, расписания трансферов и таймингов заселения.

**Основные переменные окружения (`.env.example`):**
- `APP_PORT` — порт приложения внутри и снаружи (по умолчанию `8080`).
- `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` — реквизиты PostgreSQL.
- `NEO4J_URI`, `NEO4J_USER`, `NEO4J_PASSWORD` — реквизиты подключения к Neo4j.
- `OPENAI_API_KEY` — ключ OpenAI-совместимого API (опционально; при отсутствии автоматически активен интеллектуальный встроенный Mock-оркестратор).
- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота (опционально).

## Сидирование (Zero-Touch)

Сидирование базы данных и графа выполняется **автоматически при старте контейнера приложения**:
1. Накатываются схемы PostgreSQL и активируется расширение `vector`.
2. Загружается синтетический датасет (4 направления: Сочи, ОАЭ, Турция, Таиланд с ценовыми диапазонами, внешними рисками и отелями).
3. Строится граф стыковок аэропортов, отелей и трансферов в Neo4j.

При необходимости повторное сидирование можно вызвать вручную:
```bash
docker compose exec app python -m app.seed
```

## Маршруты и доступ

### Проверки без Docker

Из корня репозитория (Python 3.11–3.12):

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
cd backend
..\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверки изоляции сессий веб-чата и обязательных ограничений подбора отелей
работают без PostgreSQL, Neo4j и внешних API. Для полного запуска приложения
по-прежнему используется Docker Compose.

Веб-чат хранит идентификатор сессии в HttpOnly cookie на 30 дней:
разные браузеры получают разные корзины, вкладки одного профиля браузера — общую.
Это разделение демо-сессий, а не авторизация пользователей.

### Бюджет поездки

Агент сохраняет общий лимит в рублях: например, «Сочи до 100 тысяч»,
«бюджет 100 000 рублей» или «уложиться в 150к». При последующих изменениях
лимит сохраняется. Новый явный лимит заменяет предыдущий.

С лимитом сравнивается **верхняя граница оценки всей поездки**: перелёт,
проживание на выбранное число ночей, трансфер, питание и активности.
Проверяются все отели выбранного направления, прошедшие обязательные фильтры,
а в ответ попадают до трёх вариантов в пределах лимита. Если вариантов нет,
агент объясняет превышение и убирает старое предложение из корзины.

«Сделай дешевле на 30 тысяч» устанавливает потолок на 30 000 ₽ ниже
предыдущей верхней оценки всей поездки. Просто «подешевле» ищет вариант
строго дешевле предыдущей оценки. Без предыдущего расчёта агент уточняет лимит.
Лимиты за ночь, на человека и в другой валюте требуют уточнения общего бюджета.
Цены и диапазоны расходов взяты из синтетического каталога и не являются
гарантией реальной стоимости; индивидуальные детские тарифы и количество комнат
пока отдельно не рассчитываются.

- `http://localhost:8080/` — интерактивный веб-дашборд и тестовый чат с AI-агентом (полная симуляция сценариев из ТЗ).
- `http://localhost:8080/health` — 200 OK, JSON `{"status": "ok", "postgres": true, "neo4j": true, ...}`
- `http://localhost:8080/api/chat` — REST API эндпоинт отправки сообщений агенту.
- `http://localhost:8080/api/stats` — статистика графа логистики (число городов, отелей, аэропортов и трансферов).


## Условия поиска и предупреждения

Над результатами показаны учтённые даты, состав гостей, питомцы, общий бюджет
и требование отдельного номера. Неуказанные условия отмечены как требующие
уточнения. Сводка обновляется при изменении поездки и остаётся видимой,
если подходящих отелей нет.

Ожидание заселения и пересадка показаны рядом с рейсом, превышение общего
бюджета — рядом со стоимостью. Ожидание считается от прибытия в отель после
получения багажа и трансфера. Для самостоятельного трансфера отдельно
указано, что дорогу и её оплату путешественник организует сам.

## Ранжирование CatBoost LTR

В проект включена модель `backend/app/data/catboost_travel_ranker.cbm`.
После обязательных фильтров и расчёта доступных пакетов она оценивает кандидатов
по 10 признакам и пяти архетипам: `pet`, `family`, `luxury`, `budget`, `solo`.
Обычно рассматриваются до 30 отелей; при заданном лимите бюджета проверяется
весь отфильтрованный каталог. Пользователь и LLM-консьерж получают итоговый top-3.
Для составных туров отели ранжируются отдельно для каждой части маршрута.

Фильтры по детям, питомцам и отдельному номеру применяются до ранжирования.
В одиночных турах заранее проверяется и верхняя оценка всего бюджета.
Сохранены приоритеты дешёвых и премиальных вариантов; при равной цене учитывается
ML-скор. В составном туре итоговая стоимость проверяется после сборки маршрута,
при превышении лимита показывается предупреждение. Если подходящих отелей нет,
возвращается пустая выдача с сохранением условий поиска.

Статус доступен в `/health`, `GET /api/ltr/status` и окне диагностики.
При успешной загрузке и инференсе используется `CatBoostRanker (.cbm)`,
при отсутствии библиотеки, весов или ошибке модели — `Analytical fallback`.
Docker при сборке проверяет наличие и загрузку модели из скопированного каталога `app`.

`POST /api/ltr/feedback` принимает `archetype`, словари `chosen_tour`,
`rejected_tour` и целый `margin` от 1 до 10. Буфер ограничен 10 000 событиями
на процесс и очищается при перезапуске. Это сбор сигналов для последующего анализа;
постоянное хранение и автоматическое дообучение пока не реализованы.

Переобучение с собственным JSONL-датасетом запускается из `backend`:

```bash
python -m app.scripts.train_ltr --input path/to/pairs.jsonl --output-model app/data/catboost_travel_ranker.cbm
```

Исходный обучающий JSONL в репозиторий не включён. Скрипт проверяет пары и признаки,
разделяет данные по `pair_id` без утечки между train/test и выводит NDCG@2 и pairwise
accuracy. Модель обучена на синтетических данных: для части направлений используются
категориальные маршруты-прокси, а при отсутствии расстояния до центра — расстояние
до моря как приближённый признак. Реальные города и логистику определяют каталог и Neo4j.

## Память предпочтений и операции с бронью

В одном профиле браузера агент сохраняет предпочтения в PostgreSQL между открытиями
страницы и новыми диалогами (cookie действует 30 дней). Сохраняются интересы,
состав путешественников, питомцы, отдельный номер, аэропорт и пожелания к перелёту.
Кнопка AI Travel Planner начинает новую поездку: даты, бюджет, корзина и история
очищаются, предпочтения остаются. Они отображаются над чатом; кнопка
«Забыть предпочтения» очищает и память, и текущую поездку. Новые явные условия
(например, «без детей и без собаки») заменяют прежние. На другом устройстве
или после удаления cookie память не восстанавливается: авторизация пока отсутствует.
Telegram использует стабильный идентификатор пользователя и ту же память профиля.

GET /api/profile возвращает сохранённые предпочтения текущего браузера.
POST /api/session/reset сохраняет их по умолчанию; тело
{"forget_preferences": true} позволяет забыть их.

Запросы забронировать отель, отменить или перенести оформленную бронь возвращают
заглушку BOOKING_UNAVAILABLE. Реальные и имитированные новые брони не создаются,
оплата и изменения существующей брони не выполняются, корзина сохраняется.
Обычное изменение дат плана поездки продолжает работать. Существующий демонстрационный
чекаут в коде инструментов оставлен для совместимости, но из чата больше не вызывается.

Проверки: python -m unittest discover -s tests -v из backend.
