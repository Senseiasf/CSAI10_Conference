# Исправление бенчмарка CSAI-200

Работа выполнена в `codex/fix-benchmark-validity` на основе
`origin/feat/exp-minilm-and-graph-validation` (`0a6d405`).

| Проблема | Что изменилось |
| --- | --- |
| Победитель пары всегда стоял первым | Позиции A/B назначаются до определения победителя и сохраняются вместе с меткой. Прогнозы, ничьи и матрица ошибок считаются по этому порядку. При нулевом знаменателе метрика остаётся неопределённой. |
| Подстановка невалидного пула в C3/C4 | Строгие режимы ранжируют только допустимые пакеты. Если их нет, выдача пуста. Учитываются кандидаты обоих найденных направлений. |
| Срезы каталога и несвязанные сегменты | Пакет собирается по связке аэропорт вылета → аэропорт прилёта → отель. Обратный рейс ищется по обратной паре аэропортов. C3/C4 читают связи и свойства реальным Cypher-запросом. Список путей сверяется с каталогом. |
| Две версии логистических правил | Бенчмарк использует общие правила буфера и трансфера из `GraphService`. Для гидросамолёта проверяется готовность после 80-минутного буфера, для моста — расчётное время пересечения конкретным трансфером. Проверяются обе стыковки и известная вместимость. Отбракованные и выданные варианты считаются отдельно. |
| Эталонные слоты скрывали ошибки NLU | `--slots oracle` явно обозначает проверку компонентов на эталоне. В `--slots live` кандидаты строятся по результатам NLU, а оценка сверяет выдачу с эталоном. Неизвлечённые обязательные слоты приводят к состоянию уточнения. |
| Игнорирование города и перекос описания ОАЭ | Именованные направления проверяются по топонимам и словоформам до векторного поиска. В описании ОАЭ отражены также семейные парки, набережные и апартаменты. C1 при отсутствии совпадения возвращает пустой список. C2–C4 используют MiniLM для неявных запросов. |
| Пары с невалидными вариантами | Общий набор пар для всех ранжировщиков строится из допустимых туров одного запроса. Живой судья видит время вылета обоих туров и может вернуть ничью. Старая разметка не переиспользуется. |
| Произведение метрик и расходящиеся таблицы | Введена наблюдаемая `Success@3`: доля запросов с хотя бы одним одновременно релевантным, логистически допустимым и удовлетворяющим условиям туром. CSV, JSON, LaTeX и графики получают показатели из одного расчёта. Покрытие вынесено отдельно. |
| Бюджет в разметке менялся без изменения текста | Генератор записывает признак выполнимости без подмены бюджета и не добирает квоту из недедуплицированного пула. В замороженном наборе исправлены три явно расходившихся суммы: CSAI_009, CSAI_128 и CSAI_139. |

## Проверенный прогон

200 запросов, реальные Neo4j 5.21, MiniLM 384D и CatBoost. Режим
`--slots oracle --retrieval numpy --judge pareto`. Семантический поиск
вычислялся точным косинусным сравнением. Для отдельных прогонов доступны
проверяемый снимок pgvector и живой NLU/судья при наличии провайдера.

| Режим | Hit@2 | LFR@3 | CSR@3 | Success@3 | Покрытие |
| --- | ---: | ---: | ---: | ---: | ---: |
| C1 | 30,5% | 21,5% | 9,17% | 13,5% | 30,5% |
| C2 | 86,0% | 62,5% | 26,33% | 25,5% | 100,0% |
| C3 | 86,0% | 95,0% | 95,0% | 61,0% | 95,0% |
| C4 | 86,0% | 95,0% | 95,0% | 61,5% | 95,0% |

- Для C3/C4 проверены все записи выдачи. Нарушений логистики и эталонных
  ограничений нет. Десять пустых выдач в каждом режиме дают ноль в LFR и CSR.
- По каждому строгому режиму зарегистрировано 87 кандидатов с нарушением
  времени готовности к гидросамолёту. В выданных пакетах таких нарушений нет.
- Запрос CSAI_049 выбирает ОАЭ. На текущих 20 запросах, где ОАЭ стоят первыми
  в эталоне, Hit@1 и Hit@2 составляют 100%. Описание направления уточнено
  в ходе аудита этой выборки. Проверка переноса требует новых запросов.
- В диагностическом наборе 182 пары с однозначным Парето-доминированием.
  У 89 пар эталон A, у 93 — B. Для C4 получены TP=88, FP=5, TN=88, FN=1.
  Цена и эвристика получили 100%, CatBoost — 96,70%. Здесь победитель по
  определению не дороже и не хуже по выбранным признакам. Эти числа
  описывают диагностический тест доминирования, а качество пользовательского
  выбора между компромиссами остаётся отдельным экспериментом.
- Success@3 у C4 выше C3 на один запрос. Этого наблюдения недостаточно,
  чтобы утверждать устойчивое преимущество модели.
- Прошли 37 тестов через `unittest`, включая регрессии 59/60 минут,
  гидросамолёт 15:10/15:11, мост, вместимость, отказ, топонимы, порядок пар,
  бюджет и колонки LaTeX. Проверены Ruff и `git diff --check`.

## Воспроизведение

Из `backend/` с доступным Neo4j, заполненным тем же каталогом:

```powershell
python -m unittest discover -s tests -q
python -m app.scripts.run_csai_benchmark --slots oracle --retrieval numpy --judge pareto
python -m app.scripts.plot_csai_figures
```

Файлы прогона в `experiment_outputs/`. В JSON сохранены контрольные суммы
каталога, запросов и модели, режимы запуска, кандидаты выдачи и причины отказа.
CSV и LaTeX содержат те же показатели. Полный прогон с `--retrieval pgvector`
и `--slots live --judge live` в этой среде не проверен. Для статьи он нужен
отдельно от диагностики Парето. Тарифы и расписания остаются снимком каталога.
Неизвестная вместимость, календарная доступность и условия совместного билета
из этого снимка не восстанавливаются. C2 → C3 включает фильтрацию и смену
ранжировщика, поэтому разницу нельзя целиком приписать Neo4j.
