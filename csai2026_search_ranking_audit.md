# Поиск, ранжирование и покрытие графа — 11.11.2026

## Исправления

- SHA-хэш слов заменён настоящей multilingual MiniLM. Ревизия модели закреплена;
  нормализованный результат проецируется с 384 до 128 измерений фиксированной
  ортонормированной матрицей. На реальном инференсе косинус «море»/«морю» ≈ 0,98,
  «море»/«пляж» ≈ 0,87, «море»/«бухгалтерия» ≈ 0,29. Запятая не меняет вектор.
  Это проверка семантики модели, не метрика качества всей поисковой выдачи.
- Seed пересчитывает эмбеддинги и сохраняет `embedding_version`. SQL-поиск исключает
  старую версию; прямой поиск по названию остаётся доступен. Инференс запросов вынесен
  из event loop. Пустые запросы и противоречивые географические фильтры дают пустую выдачу.
- Удалён отдельный жёсткий список «морских направлений», перекрывавший семантику.
  Прямые совпадения соблюдают ограничения Россия/заграница, включая Грузию.
- Бюджет больше не пересортировывает уже ранжированные пакеты по звёздам. Жёсткие
  ограничения применяются до выбора. Явное пожелание дешевле сохраняет ценовой приоритет.
- ОАЭ, Таиланд, Мальдивы и Египет больше не выдаются модели за Турцию; СПб и Алтай
  получили собственные категории. Неизвестное направление не подменяется Сочи.
  Удалены фиктивные 25 000 ₽ транспорта в признаке цены при отсутствии полного пакета.
- Обучение CatBoost использует отдельные train/validation/test группы. Test больше
  не участвует в early stopping. Ничья предсказаний даёт 0,5 в pairwise accuracy.
- Исправлены две ссылки трансферов на несуществующие ID тайских отелей. Удалена
  устаревшая запись трансфера Boathouse, дублировавшая существующий актуальный маршрут.
  Добавлена проверка ссылочной целостности до записи графа: потеря рёбер через MATCH
  больше не проходит незаметно. Вместимость и мостовые ограничения передаются также
  межотельным рёбрам. Неизвестные характеристики рейса не заменяются Airbus/багажом 23 кг.
- Составной тур перебирает пары отелей, проверяет доступность транспорта и полный
  бюджет, использует цены найденных сегментов. При отсутствии рейса нет подстановки
  TK-2415 из шаблона. Межотельный переезд учитывается один раз и остаётся обязательным
  при отказе от аэропортовых трансферов. Одна ночь не превращается в две ночи проживания.
- Наземный сегмент после внутреннего рейса проверяется с аэропортовым буфером,
  вместимостью, окном гидросамолёта и мостовыми ограничениями. Ответ о расписании
  использует сохранённый маршрут; без него сообщает об отсутствии данных.
- Удалены придуманные скидки вторника и наценки выходных. Изменение даты само по себе
  не создаёт экономию. Календарь сообщает, что конкретных тарифов поставщика нет.
- Удалено фиктивное оформление/оплата в `checkout_cart`. Возвращается
  `BOOKING_UNAVAILABLE`, выбранный план сохраняется. API поставщика бронирования
  не подключён; это явная недоступность возможности, а не выполненная операция.

## Оставшиеся ограничения и следующий этап

1. Каталог демонстрационный. У 100 из 276 записей рейсов нет обратной пары; у 1 357
   из 1 360 трансферов не указана вместимость. Наличие связи не доказывает доступность
   мест, движение по конкретной дате, вместимость или актуальную цену. Эти значения
   нельзя достоверно восстановить из текущих файлов.
2. Только 8 межотельных рёбер: строгая проверка закономерно отвергает многие составные
   туры. Требуются проверенные маршруты и остановки, включая отели второго города
   для непокрытых конфигураций. Нельзя создавать обратные рёбра простым копированием.
3. Нет тарифа одного внутреннего авиасегмента и открытого маршрута туда/обратно
   через разные города. Сейчас используется явно обозначенная оценка каталога.
   Обратный наземный трансфер не подтверждён и не включён. Семантика цены некоторых
   трансферов «на человека/на машину», остаток мест, временные зоны, переход суток
   и подтверждение ночного заселения требуют полноценной модели инвентаря.
4. Веса CatBoost не переобучались: исходный размеченный датасет отсутствует. Новые
   категории и изменения признаков требуют обучения и отложенного эксперимента.
   Улучшение NDCG в этой ветке не заявляется. Сумма гостиничных скоров для пары —
   эвристика, не обученный ранжировщик многогородских маршрутов.
5. Старый seed обновляет/добавляет записи, но не выполняет полную синхронизацию удаления
   произвольных устаревших данных. Для воспроизводимых экспериментов нужен отдельный
   чистый каталог или версионирование всех управляемых узлов/рёбер.
6. Четыре экспериментальные конфигурации C1–C4 пока не выделены. Флаг ослабленной
   графовой проверки не заменяет отдельные базовые варианты. Это остаётся задачей
   интеграции; текущий код — единый агент с сервисами поиска, графа и ранжирования.
7. Полный PostgreSQL/pgvector и Docker-build локально не проверены: Docker отсутствует.
   Модель и зависимости установлены и проверены в Windows `.venv`.

Перед запуском обновлённого приложения нужен повторный seed векторного каталога.
Старые хэш-векторы и новая MiniLM не должны сравниваться в одном пространстве.
