# Попарный тест сохранённого CatBoost V2 и эвристики C3

Ветка `review/csai2026-audit-fixes`, коммит `f572e1071ea463186e1657a4e9dbd67a4fd2813a`. Проверены сохранённый `catboost_travel_ranker_v2.cbm` (17 деревьев), действующая взвешенная эвристика `_surrogate_score` и сортировка по цене, которую использует C2-G. Оценки получены штатной функцией `scores` для всех 402 размеченных пар. Хеши модели и входных файлов проверены до и после прогона.

Для каждой пары использован записанный выбор судьи. В первом прогоне использованы признаки из файлов разбиения. Во втором признаки тех же пакетов пересчитаны штатным `candidate_pool` из полного допустимого пула соответствующего направления при известных параметрах поездки. Полные цены во втором прогоне совпали с ценами, которые видел судья. В обоих прогонах правила сравнения одинаковы для всех методов. При равенстве оценок с точностью `1e-6` выбирается меньшая цена. Если цены также равны, засчитывается половина правильного ответа независимо от порядка A/B. Подъём предпочтительного предложения и разнообразие выдачи в тесте отсутствуют. Каталог прочитан из JSON. Измеряется порядок пары внутри направления.

Строки train отражают поведение на обучающем разделе. Они включены для диагностики. Расхождение с ранее полученными 80/105 у цены на сохранённых признаках связано с учётом ничьих. Старый скрипт при равной цене выбирает B.

При расчёте признаков по каталогу на test CatBoost опережает C3 на 22 ответа. Только CatBoost прав в 44 парах, только C3 — в 22. Цена опережает CatBoost на 13 ответов. Только цена права в 37 парах, только CatBoost — в 24. На validation порядок другой. C3 получил 87/105, CatBoost — 56/105. При переходе с сохранённых признаков на каталог CatBoost меняет сторону выбора в 18 тестовых парах.

| Test, признаки из каталога | Пар | Цена | C3 | CatBoost V2 |
|---|---:|---:|---:|---:|
| Судья выбрал более дешёвый пакет | 80 | 80 | 23 | 43 |
| Судья выбрал более дорогой пакет | 25 | 0 | 22 | 24 |

CatBoost воспроизводит 24 из 25 решений в пользу более дорогого пакета, но только 43 из 80 решений в пользу более дешёвого. Например, на семействе «бюджетный запрос, завтрак или цена, Сочи» CatBoost получил 0/21, цена — 21/21. На семействе «комфорт или цена, Турция» CatBoost и C3 получили по 21/21. Подробные результаты по всем семействам есть в `summary.json`.

В validation и test по пять семейств. Пары внутри семейства используют общие условия и повторяющиеся пакеты. Поэтому 105 пар в разделе не дают 105 независимых наблюдений. Разметка получена от LLM-судьи и уже использовалась в диагностике проекта. Эти результаты описывают существующий корпус компромиссов. Для оценки обобщения нужен независимый набор размеченных семейств. Поскольку при пересчёте меняются цена и контекст доплаты, этот тест измеряет чувствительность ко всему переходу на признаки из каталога. Он не отделяет эффект каждого признака и не устанавливает переобучение.

Воспроизведение из корня проекта:

```powershell
.\.venv\Scripts\python.exe audit/review_f572e10/test_frozen_rankers.py --output-dir experiment_outputs/frozen_rankers_f572e10
```

`summary.json` содержит хеши и агрегаты, `pairs.jsonl` — оценки обеих карточек, предсказания и баллы для каждой пары в обоих прогонах.
